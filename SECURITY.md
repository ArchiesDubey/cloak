# Security Policy & Threat Model

Cloak is designed from the ground up as a security-critical, local-first secrets manager and process runtime. We take the security of your credentials, keys, and environments seriously.

---

## Reporting a Vulnerability

If you discover a security vulnerability or potential threat in Cloak:

1. **Do NOT report security vulnerabilities via public GitHub issues.**
2. Please report security concerns via **GitHub Private Vulnerability Reporting** on the repository page (`Security` tab -> `Advisories` -> `Report a vulnerability`).
3. Alternatively, you may contact the maintainers directly via email: `archiesdubey1@gmail.com` with the subject `[SECURITY] Cloak Vulnerability Report`.
4. Please include:
   - A description of the issue and potential impact.
   - Exact steps or proof-of-concept to reproduce the behavior.
   - Operating system and Cloak version (`cloak --version`).

We will acknowledge receipt within 48 hours and work with you on a coordinated disclosure timeline.

## Threat Model & Security Boundaries

### What Cloak Protects Against (In-Scope)

1. **Accidental Repository Leaks**:
   - Eliminates plaintext `.env`, `.env.local`, or secret config files residing in project directories that could be committed to Git.
2. **Third-Party Dependency & Extension Snooping**:
   - Build scripts, malicious npm packages, or rogue IDE plugins scanning local directory trees for `.env` files find nothing.
3. **Shell History & Argument Leaks**:
   - Secrets are **never** passed as CLI arguments (which appear in `ps aux`, `/proc/<pid>/cmdline`, or Activity Monitor).
   - Injected strictly into the child process environment memory (`execve`).
   - The parent shell environment is never modified (`env | grep SECRET` returns empty).
4. **Clipboard Scraping & History Monitors**:
   - On macOS, copies set concealed pasteboard markers (`org.nspasteboard.ConcealedType`, `org.nspasteboard.AutoGeneratedType`), instructing clipboard managers (Raycast, Alfred, Maccy, Paste) not to record credentials.
   - Enforces automatic 30-second clipboard memory wiping guarded by change-count comparison.
5. **Memory Dump Extraction**:
   - Core dumps are disabled on Unix (`setrlimit(RLIMIT_CORE, 0)`).
   - All secret memory buffers are held in `zeroize::Zeroizing<String>`, zeroing memory immediately upon deallocation.
6. **Agent Over-Privilege**:
   - `--keys KEY1,KEY2` enforces least-privilege, preventing sub-agents or scripts from receiving keys outside their assigned scope.

### What Is Outside Cloak's Threat Model (Out-of-Scope)

1. **Host-Level Root/Admin Compromise**:
   - If an attacker has `root` / `sudo` access, kernel-level capabilities, or can attach debuggers (`lldb`, `gdb`) to running PIDs, process memory can be dumped regardless of user-space protections.
2. **Intentional Exfiltration from Inside the Process**:
   - If a script is explicitly programmed to read its own memory or write its own environment variables to disk (e.g. `python -c "import os; print(os.environ)"`), Cloak cannot prevent the child process from doing so.
3. **Hardcoded SSL Pinning**:
   - Applications that hardcode specific upstream TLS certificate hashes will reject any local CA, including Cloak's MITM proxy. (For such binaries, use `cloak run -- <cmd>` rather than `--proxy`).

## Cryptographic Specifications

- **Key Derivation Function (KDF)**:
  - Argon2id (`argon2` v0.5)
  - Memory: 65,536 KiB (64 MiB)
  - Iterations: 3
  - Parallelism: 4
- **Authenticated Encryption with Associated Data (AEAD)**:
  - XChaCha20-Poly1305 (`chacha20poly1305` v0.10) with 192-bit CSPRNG nonces
- **Hardware Access Control**:
  - macOS Keychain Services (`Security.framework`) with `SecAccessControl` (`kSecAccessControlUserPresence` / `kSecAccessControlBiometryAny`).
